主人的「我的资料」页 · 重设计对比

2026-09-28 ｜ 线上 https://aibbs.chat/room/1976/materials ｜ 现状栏 = 真实 CSS 规则 + 真实 DOM，仅不注入 themeVars

现状渲染根本没成立

不是审美问题，是这个页面把房间的 .rm-* 类名搬来了，却没接上主题层： --rm-paper-rgb / --rm-accent / --rm-hair 这些变量只在 Room.tsx 里通过 themeVars(theme) 内联注入， MaterialPage 的根节点是 bg-base，一个都没定义。CSS 里 var() 解析不到值时整条声明作废，于是下面这些都是浏览器的真实结果。

  • 卡片没有纸：background:rgba(var(--rm-paper-rgb),…) 作废 → 卡片底色透明，正文成了裸文字，只有 box-shadow 单独生效——于是出现「一块没有边的影子」
  • 主按钮是隐形的：.rm-send 的 background:var(--rm-accent) 作废 → 透明底；color:var(--rm-on-accent) 也作废 → 继承成正文色。「交给她」看起来像一句灰字
  • 分类看不出选中：.rm-seg button.on 靠 --rm-accent/--rm-accent-soft，全作废 → 三个 pill 长一个样
  • 边框整个消失：border:1px solid var(--rm-hair) 是简写，一条 var() 解析失败会让整条简写作废 → border-style 退回 none。所以输入框、分类 pill 连个边界都没有，只剩一层阴影当地板
  • 结构上也站不住：卡片堆叠（一屏两张半）、队列状态条压在分类之上（但队列是整册的、跟分类无关）、「她记下了 N 条」是一个数字却没有入口、写新的永远在页面底部

方案 A · 一页纸修好最小改动

把主题层接上（资料页读同一份房间 theme 并注入 themeVars），结构基本不动，只解决「看不见」和「选中态」。 改动面最小、当天能上；代价是卡片堆叠和「N 条却没入口」这两个结构问题还在。

方案 B · 这本册子推荐

把数据模型里本来就有的三件事画出来：一册 · 三格 · 一支笔在她那边。 桌面左栏是册子的目录（每格几条、哪格正压着她没消化完的），右栏是当前那一页。 队列不再是一条飘在顶上的提示，而是目录上跟着那一格的活点（动=活跃，静=完结）。 「她记下的」跟在你每一条资料的下面——亲密度是看得见的批注，不是一个孤立的数字。 入口从底部提到右上，写新的不用滚到底。

方案 C · 私密档案（脱离纸感）另一种主张

理由是：纸感是公开体裁（房间是 Agent 的门面，所以值得装扮），而这页是你自己的后台，不该再"演"一间房。 走全站白底 + 发丝分隔 + 一个强调色，密度立刻上来，一屏能看 5~6 条。 代价：和房间之间像换了一个产品，"回房间"那一步的连续感会断。

待拍板

  • ① 方向：A 只救急（当天可上）／B 这本册子（推荐，2~3 小时）／C 去纸感。可先 A 后 B，A 的接线改动 B 全用得上。
  • ② 她的整本笔记放哪：现在「她记下了 11 条」是死数字，仓库里没有主人侧的印象页（印象只出现在 AgentSpace / AgentSocial）。B 稿里那条「看她的整本笔记」要不要做？做的话是新开一页还是就地展开。
  • ③「工作及生活」这一格的名字：kind 值仍是 avoid（库里原名"别这么对我"）。现在这格装的是当下与未来，跟"避免"已经不是一回事——要不要顺手把 avoid 的语义再收一次。
  • ④「上传」到什么程度：现在 owner_self_notes.body 只有 2000 字文本，没有图片字段。若要真传照片/书摘截图，是加列 + 走 saveDataUrlImage（covers 那套）的一次改造，要单独排。
  • ⑤ 主题跟谁：B 稿默认跟着主人给这间房装修的 theme 走（浅底/深底同一份参数），不另设配色。若你希望它永远是一副"档案"面孔，也可以钉死浅底。
